# Acceptance guidance

Validate the final SDK artifact, not only source compilation. Record Android version, sender model, receiver model and app version, network type, SDK version, callback codes, and evidence for each result.

- Bind with valid and invalid credentials.
- Generate a clean project and verify it is a Git work tree before onboarding. Run `scripts/onboard.py --project-dir <project> --app-name "<application name>" --check`; verify omission of either required argument fails at argparse, while the full command reaches project/credential validation. Confirm `local.properties` and generated `SkillSdkConfig.java` remain ignored.
- Before each Debug and Release build using Skill-managed credentials, run the same full onboarding `--check` command and require `SDK credential mapping is valid: APP_SECRET uses platform md5Key.` Verify that a generated config using platform `secret`, a mismatched `APP_ID`, and a missing config each fail the check without printing credential values. For a pre-existing host-managed credential pair, verify that both non-placeholder arguments remain connected to `setSdkInitInfo` without printing them, and verify that no registration or login was triggered.
- Verify the host resolves `androidx.core.content.ContextCompat` and `androidx.core.app.NotificationCompat` from an explicit AndroidX Core dependency. Start the mirror path; a successful compile without this runtime exercise does not pass.
- Inspect the final merged Manifest for both Debug and Release. Each `<application>` must contain `android:usesCleartextTraffic="true"` and a resolvable non-zero `android:icon`; a source-only declaration does not pass acceptance. If `android:networkSecurityConfig` is present, verify its effective policy also permits cleartext traffic. Complete MediaProjection consent and require the foreground notification to post without `Bad notification for startForeground`.
- Require merged `android.hardware.usb.host` to have `android:required="false"` unless USB is an explicit product requirement. Inventory merged permissions and components, including overlay, legacy storage, audio/foreground-service permissions, USB components, and `LelinkAccessibilityService`; remove unused declarations and record the store/privacy treatment for retained ones.
- With the target Gradle Wrapper absent, verify environment preparation reuses an exact Gradle distribution already under `GRADLE_USER_HOME/wrapper/dists` without contacting `services.gradle.org`. Also test the documented proxy or repository-mirror path for a network where official AGP/dependency repositories are unavailable.
- Verify that an explicit capability request proceeds without a casting-scope prompt. For an incremental request, verify that the SDK artifact, credentials, initialization, discovery, connection, and already working casting mode are preserved while only the requested capability is added. When a new/full integration remains ambiguous, verify that the scope prompt lists `1. 仅媒体推送（默认）`, `2. 仅手机屏幕实时镜像`, then `3. 媒体推送 + 手机屏幕实时镜像`; a 30-second timeout reports and selects option `1`, which adds no mirroring-specific permissions or services.
- Capture `onBindCallback`, each distinct `onBrowse(resultCode, list)` state and copied count, the suppressed-identical-callback count, the selected device transition, and every connection callback. Feed at least 100 identical success callbacks and verify the internal snapshot updates while logs and UI renders remain bounded.
- Discover a Lelink receiver whose App ID maps to a `type == 1` APK channel, an environment containing only other channel types or devices without App ID metadata that returns `BROWSE_NO_LEBO_DEVICE`, and an environment with no responses that returns `BROWSE_MULTICAST_BLOCKED`.
- Start discovery, temporarily cover the host UI with the QR camera and a system permission screen, then return. Verify UI observer detachment does not call `stopBrowse()`, discard coordinator state, or register duplicate SDK listeners.
- Refresh during an active browse and verify stop/restart is serialized through `BROWSE_STOP`, with no overlapping browse tasks. Separately start a browse and make no stop call; verify the SDK's automatic `BROWSE_STOP(2)` after roughly 30 seconds is handled as normal window completion and preserves the last list.
- Compile both QR and PIN calls with an explicitly typed `IServiceInfoParseListener`; a bare ambiguous lambda fails acceptance. Parse a valid and unsupported target, record camera decode result separately from `onParseResult`, verify the SDK can read the receiver's private-IP HTTP `DnsTxtInfo` without a cleartext-policy exception, and verify successful parse passes its exact returned object to `connect()` with a non-empty App ID belonging to a `type == 1` channel.
- Select an item from the latest browse snapshot, connect its exact `LelinkServiceInfo`, verify success only from `onConnect`, then reconnect, disconnect, and connect a second receiver.
- For an ordinary application with mirroring enabled, inspect every constructed `LelinkPlayerInfo` and require `useSystemMirrorCapture` to remain unset/default `false` or explicitly `false`; any `useSystemMirrorCapture(true)` fails acceptance. On a clean install, start mirroring and verify the MediaProjection consent UI appears, denial does not start capture, and approval proceeds through the permission callback into an actual mirrored frame. Test the system-capture branch only for a confirmed system application with the SDK-supported capture path.
- Cast a public URL, an unsupported local file over the public path, and an image list.
- Play one video for longer than 60 seconds and verify repeated `onStart` callbacks do not repeat session initialization, analytics, or cast commands. Call `seekTo` on a capable receiver and verify progress through `onPositionUpdate` even when `onSeekComplete` is absent; exercise timeout/error handling separately.
- Exercise image append, clear, previous, next, and ID selection.
- Exercise capability-driven controls and verify the UI hides unsupported actions.
- Test network switching, background/foreground, configuration change, process recreation, and Release/R8. Confirm transient `onPause()`/`onStop()` does not own SDK teardown.

Real receiver devices and service credentials are required for these checks; a successful Java compilation is not sufficient evidence.
