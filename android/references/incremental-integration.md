# Incremental integration

Use this path when the user asks to add or change a casting capability in an Android application that may already integrate the sender SDK. The goal is to extend the working integration without repeating project creation, SDK acquisition, application registration, login, or shared discovery and connection work.

## Detect existing integration

Inspect the selected application module before running setup scripts:

1. Find an existing sender SDK AAR or Gradle dependency.
2. Find the `setSdkInitInfo(...).bindSdk()` call and trace both credential arguments to their existing source without printing their values.
3. Find the long-lived SDK owner and its bind, browse, selected-device, and connection callbacks.
4. Detect implemented casting capabilities from their actual entrypoints, such as `startPlayMedia` for media push and `startMirror` or `startDlnaMirror` for screen mirroring.

Treat the project as an incremental integration when the dependency and initialization already exist. A working media-push flow is additional evidence that its application registration and SDK initialization credentials are reusable. Non-placeholder App ID and SDK App Secret references are sufficient to skip registration and login; they may come from `SkillSdkConfig`, `BuildConfig`, resources, constants, or another host-managed local configuration. Do not require the platform's storage-only raw `secret`: the SDK initialization value named App Secret is the platform `md5Key`.

Values that are empty, obvious examples such as `your_app_id`, or unresolved references are not reusable credentials. Report that finding without displaying credential contents, then use the onboarding workflow only if the requested work cannot proceed without a real pair.

## Choose the target capability

An explicit user request determines the scope. Do not show the casting-scope menu in these cases:

- Existing media push plus a request to add screen mirroring means preserve media push and add mirroring.
- Existing mirroring plus a request to add media push means preserve mirroring and add media push.
- A request naming only one mode means implement that mode without asking the user to select it again.

Use the three-option casting-scope menu only for a new/full integration when the user's requested capabilities remain ambiguous.

## Reuse before adding

Preserve the installed SDK version, application identity, credential source, initialization, coordinator, discovered `LelinkServiceInfo`, and successful connection gate. Do not download or replace the AAR unless the requested API is absent from the installed artifact or the user requested an SDK update. Add only the missing capability, its UI, callbacks, permissions, MediaProjection consent, notification, foreground service, and lifecycle handling.

Do not run mutating onboarding for reusable credentials. Run `scripts/onboard.py --project-dir <project> --app-name "<application name>" --check` before builds only when the project uses credentials generated by this Skill. A pre-existing host-managed credential pair does not need to be migrated to `local.properties` or `SkillSdkConfig`; verify its two initialization arguments remain wired into the final build without logging their values.
